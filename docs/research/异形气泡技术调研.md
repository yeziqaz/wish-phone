# 异形气泡技术调研

> 来源：用户 2026-11-12 提供的《聊天异形气泡制作教程.docx》。
> 那份教程讲的是**技术**（9-slice、伪元素叠图），是一套 CSS 方法的说明，

## 一、教程讲了两套技术

### 技术 A：`border-image` + 9-slice

把一张**透明背景 PNG** 切成九块渲染：

```
┌─────────┬────────────────┬─────────┐
│ 左上角  │     上边       │ 右上角  │
│ (固定)  │   (横向拉伸)   │ (固定)  │
├─────────┼────────────────┼─────────┤
│ 左边    │   中心文字区   │  右边   │
│ (纵拉)  │  (自由拉伸)    │ (纵拉)  │
├─────────┼────────────────┼─────────┤
│ 左下角  │     下边       │ 右下角  │
│ (固定)  │   (横向拉伸)   │ (固定)  │
└─────────┴────────────────┴─────────┘
```

四个角不变形，四条边只在单一方向拉伸，中心随文字长度自由伸展。
**这就是「短消息『嗯』和一大段话共用同一个气泡样式」的原理。**

语法：

```css
border-image: url("...")  85 80 45 80  fill / 55px 32px 22px 32px  stretch;
/*            ↑图片来源   ↑切片值(图片像素)    ↑border实际占位(CSS像素) ↑边条填充方式 */
```

三个容易搞错的点：

1. **切片值无单位 = 图片像素**，带 `px` 才是 CSS 像素。教程原话说「90% 的教程会搞错这点」。
2. **`fill` 关键字**不给的话中心区是透明的，文字后面没有底。
3. **`border-width` 可以比切片值小** —— 那是「装饰缩小」的手段，不必须等于切片值。
   反过来（占位大于切片）会把角拉变形。

前提：图片必须是**真透明**的背景。JPG 不行，PNG 边缘留白也不行，
否则四角会出现白方块。

### 技术 B：`::before` / `::after` 叠图

每个元素天生有两个伪元素，各自可独立定位，且能超出元素边界（`overflow: visible`）。
再加 `background-image` 支持多层逗号分隔，理论上是无限层。

两条坑：

- **多层 background 的顺序是「顶在前、底在后」**，和 HTML 层叠顺序（先写的在下）相反。
  写反了就看不到装饰。
- 伪元素必须 `pointer-events: none`，否则会拦截气泡的点击。

### 两者组合

9-slice 管**形状**，伪元素管**浮动装饰**，多层 background 管**底纹**。
三层叠起来才是完整效果。

## 二、对我们的落差分析

### 已经有的（不需要学）

| 教程能力 | 我们的对应实现 |
|---|---|
| 伪元素叠装饰 | `beauty/render.ts` 的 `bubbleStickersHTML` —— 已有四角贴纸，可调位置/缩放/旋转 |
| 多层装饰 | `Sticker[]` 数组，不限层数 |
| 装饰不拦截点击 | `.bubble-sticker { pointer-events: none }` |
| 装饰超出气泡边界 | 已支持（绝对定位 + translate） |
| 填充色 / 渐变 / 透明度 / 边框 / 圆角 / 阴影 | `beauty/css.ts` 全部覆盖 |
| 用户导入 PNG | `store.ts` 的 `importAsset`，PNG/WebP 3MB 上限 |

**结论：教程的「技术 B」我们其实已经做完了**，只是不知道它叫这个名字。

### 缺的（这才是重点）

**气泡的形状。** 我们现在的气泡永远是圆角矩形 ——
`radius: 0~36` 只是把矩形画圆一点，画不出云朵边、便笺、丝带、对话框尖角。

教程里所有「异形」的例子，形状都来自 9-slice 那张图。
**没有 9-slice，就没有异形。**

实测四个形状在 200×110（短消息）和 340×130（长消息）两种尺寸下的结果。

## 六、实测结果：哪些形状真的能用

| 形状 | 短消息 200×110 | 长消息 340×130 | 结论 |
|---|---|---|---|
| 对话框 | 尖角完整 | 尖角完整 | ✅ 最好用 |
| 邮票 | 锯齿清晰 | 锯齿清晰 | ✅ 抗压缩 |
| 便笺 | 胶带在角上 | 胶带在角上 | ✅ 可用 |
| 云朵 | **上下被压扁** | 完好 | ⚠️ 短消息会变形 |
| 丝带 | — | — | ❌ 已删（见下） |

**云朵的问题**：短消息时高度不够，上下两排弧线被挤到一起。
这是九宫格中心区纵向压缩的固有结果，不是画错。
缓解手段是 `.msg-bubble.has-shape` 的 `min-height: 64px`，
但要彻底解决得给不同高度准备不同切片 —— 不值得。

**丝带为什么删了**：燕尾切口要求左端是向内凹的尖角，
切完之后右端没有对称形状，怎么调都像「被裁掉一角」。
放一个自己看着别扭的预设，比少一个更糟。

## 七、第一版画法上的两次失败（留给后人）

1. **云朵第一版**：矩形 + 一排圆叠上去。九宫格一切，圆和矩形错位，
   露出接缝和半截圆。
   → 教训：形状必须是**单条闭合路径**，不能靠叠图。

2. **邮票第一版**：矩形 + 一排白圆孔当齿。
   渲染后孔全露在矩形描边外面，因为孔画在矩形**之上**。
   → 教训：装饰要让**路径本身**长出来，不是盖上去。

## 四、教程里值得抄的细节（不是代码，是经验）

1. **切片值按「角要包含所有固定装饰，边要只有可重复的纹理」量。**
   这是量切片的唯一原则，比记住具体数字重要。
2. **锁宽度范围**：图中央有装饰（如猫耳）时，气泡变宽会把装饰拉开。
   用 `min-width` / `max-width` 夹住。
3. **长消息会让云朵纹理拉糊**（`stretch` 模式的固有代价）。
   解法是改 `round`（重复），或接受它 —— 日常对话不会太长。
4. **四角都有独立装饰时 9-slice 就废了**，必须换伪元素法。
   这是两种技术的分界线。
5. **日/夜、按角色换皮**：教程用 `[data-time-of-day]`、`[data-char-id]` 属性选择器。
   我们的方案机制（scheme）已经覆盖了「按角色换一套」，不需要学。

## 五、暂不采纳的部分

| 教程内容 | 不采纳的原因 |
|---|---|
| `!important` 满屏 | 教程是对别人的成品页面做覆盖；我们是原生实现，不需要靠 `!important` 抢权重 |
| `transform: scaleX(-1)` 镜像做我方气泡 | 会把文字也翻过去，还得再翻回来一次；我们可以直接画两张方向相反的预设图 |
| 用 emoji 当装饰 | 项目图标体系是内联 SVG + 单色，emoji 会破坏黑白灰基调。已有贴纸系统用的是 SVG 图形 |
| 图床外链 | 违反「不许远程资源 CDN」铁律 |
