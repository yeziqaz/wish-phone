## 2. 为什么不能直接拷 `.vue`

AGENTS.md §1 明确禁止引入 Vue / Pinia。

**这是必须当面说明的冲突**：用户要求「全部照抄」，但项目宪法禁止 Vue。
处理办法：**照抄设计，不照抄承载方式**。所有数据、数值、SVG 路径、交互逻辑
都是原样搬的，只有从 Vue 模板变成 DOM 字符串拼接。

如果用户希望连框架一起换，那是推翻 §1 的决定，需要单独确认 —— 我没有擅自做。

## 3. 头像挖孔遮罩（整套系统最关键的一行）

```css
.avatar-decoration {
  position: absolute;
  inset: -100%;
  mask-image: radial-gradient(circle closest-side, transparent 33.3333%, black calc(33.3333% + 0.5px));
}
.avatar-decoration__content { position: absolute; inset: 33.3333%; }
```

装饰层铺到头像的 **三倍大**，再用遮罩把中间 1/3（头像本体）挖空。结果是：

- 贴纸可以放到头像外面很远，不会被裁掉
- **导入的大图永远不会盖住角色的脸**

没有这层遮罩的话，用户导一张普通照片当挂件，角色的脸就糊了。

## 4. 阴影强度曲线

```ts
bubbleShadow(value) {
  if (!strength) return 'none';
  return `0 ${px(0.2)} ${px(0.4)} ${px(0.04)} rgb(61 51 66 / ${opacity})`;
}
```

原项目注释写得很清楚，照搬：

> Zero removes the entire shadow; increasing strength grows and darkens it,
> instead of only blurring the same fixed offset until it disappears.

即：强度变大时**偏移和模糊一起变大、不透明度一起变深**。
只加模糊不动偏移，阴影会摊成一片灰雾，看起来像脏了。0 必须是真正的 `none`。

## 6. 与项目宪法冲突的地方，以及怎么处理的

| 冲突 | 处理 |
|---|---|
| 原项目用 Vue + Pinia | 移植成原生 TS，设计原样保留（§2） |
| 原项目默认「我」的气泡是薄荷绿 `#A6E976` | 改成反色深底 `#111114`。**这是唯一一处主动偏离**，理由是 §4 反色块红线 + 黑白灰基调。视觉关系（我 vs 角色）完全一致 |
| 原项目挂件是粉彩色 `#e6a6ba` 等 | **保留原色**。挂件是用户主动挑的装饰，不是界面基调，粉彩在这儿是对的 |
| 原项目用 localStorage + 独立 IndexedDB 存图 | 统一走 `settings` 表 + data URL。理由：Blob 的 `createObjectURL` 生命周期容易漏、多一个库多一套异常处理。代价是记录变大，所以体积上限卡死（挂件 3MB / 背景 8MB） |
| 遮罩用 `#000` | 改成 `black` 关键字（项目禁止裸色值）。语义等价 |

## 9. 两个入口、两个作用域（第二批）

### 用户提出的三件事

1. **点了头像框，聊天里不同步** ← 真 bug
2. **头像框不该露在外面**，它是美化的一部分
3. **要两个入口**：聊天室左上角（只管聊天室）、「我」界面（聊天室 + 聊天APP全局）

### ① bug 的根因：同一个东西存了两处

| 谁在用 | 存哪 |
|---|---|
| 「我」页面 | `core/prefs` 的 `userAvatarFrame` |
| 聊天里渲染 | `beauty` 的 `participants.user.avatar.frameId` |

点了框，`prefs` 变了，美化那边没变 —— 所以聊天里看不到。
**这不是「忘了刷新」，是两个数据源。**

而且当时一共有**三个**地方能改头像框：聊天设置、「我」页面、美化面板。
三套入口写两套数据，必然对不上。

**修法**：统一到 `beauty` 一处。
`prefs` 的字段保留但不再被读，只用于一次性迁移（`adoptLegacyFrame`）——
老用户打开时把旧框搬过来，不删字段，避免破坏别的引用。

### ② 头像框从外面收进美化

- 「我」页面的 `我的头像框` 网格 → 删掉，换成一个 `聊天美化` 入口行
- 聊天设置的 `头像框` + `气泡框` 两个区块 → 删掉，换成一个 `聊天美化` 入口行

现在外面看不到任何裸露的框选择器，全在美化里。

### ③ 两个入口 = 两个作用域

| 入口 | scope | 能看到什么 | 存哪 |
|---|---|---|---|
| 聊天室（抽屉 / 聊天设置） | `room` + 角色 id | 头像挂件 / 气泡 / 聊天背景 / 字体 / 方案 | `chatRoomBeauty:<角色id>` |
| 我（「我」页面 → 聊天美化） | `me` | 上面全部 + **聊天APP** 板块 | `chatBeauty` + `chatAppBeauty` |

**为什么每个聊天室一份，不共用一张全局配置**：
用户要的是「这个角色的聊天室」。共用一张，换个角色还是同一套气泡颜色，那就不是角色的聊天室了。

**为什么聊天室会继承全局**（`loadBeauty` 里的 `else if (scope)` 分支）：
用户在「我」里调好了气泡和挂件，打开新聊天室却看到一片默认灰 —— 等于白调。
所以房间没有自己的配置时**深拷贝一份全局的**，之后的修改只影响这个房间。

**为什么是同一套面板而不是两套界面**：
那样用户要在两个地方调同一件事（气泡圆角），学两遍。
现在是同一个面板，`room` 少一个板块、`me` 多一个 —— 少学一次。

### ④ 聊天APP 全局外观管什么

只有「界面」那 6 个色位，挂在 `.chatapp` 上：
背景 / 列表与卡片 / 顶部与导航栏 / 选中色 / 界面文字 / 次要文字。

它**不碰**聊天室里的气泡和背景 —— 那些属于角色作用域。
「界面」板块在 `room` 作用域下不出现（单个聊天室没有「聊天APP背景」这种东西）。

### ⑤ 顺手清掉的重复

`bubble-style.ts` + `bubble-tokens.ts`（4 档圆角/宽度/边框/间距）
和美化里的气泡设置**改的是同一个东西**，两套并存必然打架。

用户批准后删除（含 9 条对应测试），并清掉 `chat.css` 里 127 行死样式。
测试数 130 → 133（删 9 加 12）。
