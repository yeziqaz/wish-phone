## 1. 项目基本信息

- **产品名**：愿望机
- **定位**：纯前端、免费、开源的 AIRP（AI 角色扮演）仿手机界面
- **目标用户**：从新手到资深玩家。新手打开就能用，老手能深入调整
- **设计原则**：
  - 默认界面简单，进阶功能折叠或放在下一层
  - 一个对象只在一个地方可以编辑，其他地方只显示并提供跳转
  - 越具体的设置优先级越高，没设置的跟随上一级

## 2. 术语表

| 术语 | 含义 |
|---|---|
| **站点 / API 供应商** | 一个 API 来源，包括官方直连、中转站、聚合平台。由 URL + Key 组成 |
| **Key** | API 密钥。一个站点可以有多个 Key |
| **模型** | 站点下可以调用的具体模型，通过"拉取模型"获取，由用户挑选启用 |
| **能力** | 模型能做什么。共 6 种：文本、生图、看图、生视频、语音、向量。一个模型可以有多种能力 |
| **系列** | 模型所属的厂商家族，如 Claude、GPT、DeepSeek，用于筛选 |
| **作用域** | 设置生效的范围：全局、App、角色 |
| **分配** | 某个作用域下，某种能力使用哪个站点的哪个模型 |
| **辅助模型** | 挂在某种能力下的前置工序模型，如"生图提示词改写" |
| **适配器** | 把统一请求翻译成各家 API 格式的小模块，每种协议一个 |
| **策略组** | 多个站点编成一组，轮流或故障转移使用（后续迭代） |

### 能力说明

| 能力 | 代码标识 | 用途 | 典型提供者 |
|---|---|---|---|
| 文本 | `text` | 聊天主力 | DeepSeek 等 OpenAI 兼容站 |
| 生图 | `image` | 生成图片 | NovelAI、文生图站 |
| 看图 | `vision` | 用户发图，AI 识别和描述 | 支持视觉的文本模型 |
| 生视频 | `video` | 生成视频 | 各视频生成平台 |
| 语音 | `tts` | 文字转语音 | MiniMax、Fish Audio、ElevenLabs |
| 向量 | `embedding` | 把文字转成向量，用于记忆检索 | 文本站的 embedding 模型 |

> **向量的用途**：角色记忆、历史对话、世界书条目太多时无法全部放进上下文。先把它们转成向量存起来，聊天时找出和当前内容最相关的几条，只把这几条交给模型。第一版只预留选择位置，等以后做"记忆库"功能时再接入。

## 4. 站点 Tab（API 与模型首页）

### 4.1 页面结构（从上到下）

1. **粘贴导入框**：一个多行输入框 + "识别"按钮。这是本产品的特色功能，必须放在首屏最上方
2. **站点列表**：站点卡片竖向排列
3. 右上角 "＋" 按钮：手动添加站点（不使用粘贴时）

### 4.2 站点卡片

每张卡片显示：

- 站点名
- 站点类型标签：官方直连 / 中转站 / 聚合平台
- 状态灯：绿（最近一次测试成功）/ 红（失败）/ 灰（未测试）
- 余额：能查询到就显示数字，否则显示"—"
- 已启用模型数
- 被引用次数（如"3 处使用"）

点击卡片进入站点详情。长按或左滑出现"测试连接"和"删除"。

### 4.3 空状态

没有站点时显示：
> 把你的 API 信息粘贴进来，自动填好

## 5. 粘贴导入与手动添加

### 5.1 基本要求

- **纯本地、离线可用**，识别过程不联网
- 支持一次粘贴多个站点
- 支持一个站点多个 Key
- 识别完不直接保存，先弹出确认卡

### 5.2 识别规则

**规则一（主规则，即现有格式）：按行顺序识别**

```
站点名称
https://站点地址
sk-xxxxxxxx
sk-yyyyyyyy        ← 可以有多个 Key

另一个站点名称      ← 空行或下一个名称开始新站点
https://另一个地址
sk-zzzzzzzz
```

- 名称行 → URL 行 → 一行或多行 Key
- 遇到新的"非 URL、非 Key"的行，或遇到空行后的新内容，视为新站点开始

**规则二（兜底规则）：格式不规范时智能识别**

主规则识别失败时，按以下顺序处理：

1. **URL**：匹配 `https?://[^\s"'<>，,；;]+`，去掉末尾标点。有多个 URL 时，按 URL 位置把文本切成多块，每块是一个站点
2. **Key**：在每块中匹配 `sk-`、`ak-`、`Bearer ` 开头的连续字符，或长度 ≥ 32 的字母数字串。同一块内的多个 Key 全部收入
3. **名称**：剩余文字中长度 2–20 的片段作为名称；找不到就用 URL 的域名作为名称

**附加处理：**

- **类型推断**（仅作为默认值，用户可改）：
  - 域名含 `novelai` → 生图站
  - 含 `elevenlabs` / `minimax` / `fish` → 语音站
  - 其他默认 → OpenAI 兼容
- **URL 规范化**：OpenAI 兼容站如果 URL 末尾没有 `/v1`，自动补上，并在确认卡上提示"已自动补全 /v1，可修改"。末尾多余的 `/` 和 `/chat/completions` 自动去掉
- **名称重复**：自动加后缀，如"某站 (2)"
- **Key 去重**：同一站点内重复的 Key 只保留一个

规则写在一个独立的纯函数里，输入文本、输出站点草稿数组。以后支持新格式只加规则，不改界面。

### 5.3 识别结果确认卡

- 每个识别出的站点一张卡片
- 每张卡片三项可编辑：**名称、地址、Key（多个时逐行显示）**
- 未识别的字段标黄
- 每张卡片可单独删除
- 底部按钮：**"全部保存"** 和 **"保存并拉取模型"**
- 只有点了"拉取模型"才联网

### 5.4 手动添加

右上角"＋"打开一个简单表单：名称、URL、Key（可添加多行）、站点类型。底部同样是"保存"和"保存并拉取模型"。**不在这里放任何高级选项。**

## 6. 站点详情页

### 6.1 顶部信息卡（所有 Tab 下都固定显示）

- 站点名 + 类型标签 + 状态灯
- 余额 + 刷新按钮（不支持查询的站点显示"该站点不支持余额查询"）
- 官网链接（可多条，点击直接在浏览器打开）
- 备注预览（显示一行，点击跳到"配置"Tab 编辑）
- "测试连接"按钮

### 6.2 Tab 顺序

**模型 → 日志 → 限制 → 配置**（按使用频率排序，默认打开"模型"）

### 6.3 Tab 1：模型（模型广场）

**顶部筛选栏，两行，可同时生效（"且"的关系）：**

```
能力： [全部] [文本] [生图] [看图] [生视频] [语音] [向量]   ← 可左右滑动
系列： [全部] [Claude] [GPT] [DeepSeek] [Gemini] [Qwen] [未分类]
```

再加一个搜索框，按模型名搜索。

另有一个切换：**[已启用] [全部可用]**
- "已启用"：只看用户挑选过的模型
- "全部可用"：看拉取到的所有模型，可勾选启用

**系列自动归类规则**（按模型名匹配，不区分大小写，可手动覆盖）：

| 模型名包含 | 归入系列 |
|---|---|
| `claude` | Claude |
| `gpt`、`o1`、`o3`、`o4`、`chatgpt` | GPT |
| `deepseek` | DeepSeek |
| `gemini`、`gemma` | Gemini |
| `qwen`、`qwq` | Qwen |
| 都不匹配 | 未分类 |

规则做成一张表，以后新增系列只加一行。系列按钮只显示当前站点实际有的系列。

**能力自动推断规则**（可手动修改，可多选）：

| 模型名包含 | 推断能力 |
|---|---|
| `embedding`、`embed` | 向量 |
| `tts`、`speech`、`voice` | 语音 |
| `dall-e`、`flux`、`sd`、`image`、`nai` | 生图 |
| `vision`、`4o`、`gemini`、`claude-3`、`vl` | 文本 + 看图 |
| `video`、`kling`、`veo` | 生视频 |
| 其他 | 文本 |

**每个模型条目显示：**

- 模型名
- 能力标签（可多个）
- 系列标签
- 启用开关
- 主模型标记（星标）
- 今日使用摘要：`今日 12 次 · 出错 1`
- 右侧"…"菜单：修改能力标签、修改系列、单独设置限制

**列表底部**："重新拉取模型"按钮。重新拉取时，已启用模型和用户手动修改过的标签必须保留。

### 6.4 Tab 2：日志

- 复用全站请求日志，进入时自动按当前站点过滤
- 顶部汇总：今日请求数 / 本月请求数 / Token 总数 / 错误数
- 列表每条：时间、模型名、能力、输入 / 输出 Token、耗时、状态
- 支持按模型、按能力、按状态（成功 / 失败）过滤
- 点击某条展开详情：错误信息、发起方（哪个 App / 角色）

### 6.5 Tab 3：限制

**站点级限制：**

```
并发数：      同时最多几个请求在进行     [ 3 ]    （0 = 不限）
速率限制：    每分钟最多几次请求         [ 60 ]   （0 = 不限）
超限时：      排队等待 / 直接报错        （默认：排队等待）
请求超时：    单次请求最长等待秒数       [ 120 ]
失败重试：    失败后自动重试次数         [ 1 ]
```

**顶部实时状态**：`进行中 2 / 3 · 排队 0 · 本分钟已用 15 / 60`

**模型级限制**：在模型 Tab 每个模型的"…"菜单中进入，同样的选项，默认全部显示"跟随站点"。只有用户主动修改过的项才独立生效。

### 6.6 Tab 4：配置

- **基本信息**：名称、URL、站点类型、协议类型
- **Key 管理**：
  - Key 列表，每条显示前 6 位和后 4 位，中间用 `****` 隐藏，点击眼睛图标显示完整
  - 每条有启用开关、备注名（如"主号""小号"）
  - 顶部选择使用方式：**轮询**（按顺序轮流用）/ **固定**（只用选中的一个）
  - 某个 Key 连续失败时自动标记为异常，跳过使用，并在列表中显示红点
- **官网链接**：可添加多条，每条为"名称 + 网址"，如"官网""文档""控制台"
- **备注**：多行文本，记录注意事项（如"晚高峰很慢""周末容易断"）
- **删除站点**：页面最底部红色按钮。如果有地方在使用，先提示"有 N 处在使用"，列出使用位置，点击可跳到分配页处理

### 7.3 全局设置

按组分块显示：

```
核心
  文本模型            [选择器]
  备用文本模型        [选择器]（可选，主模型失败时自动使用）

创作
  生图模型            [选择器]
    └ 提示词改写      [ 关闭 / 跟随文本模型 / 指定模型 ]
  生视频模型          [选择器]
    └ 提示词改写      [ 关闭 / 跟随文本模型 / 指定模型 ]

理解
  看图模型            [选择器]
  向量模型            [选择器]

语音
  语音模型            [选择器]
```

**提示词改写的作用**：用户输入"画一个雨天的教室"，先交给改写模型扩写成详细的生图提示词，再交给生图模型。关闭时直接使用原句。

### 7.4 App 设置

- 列出所有功能性 App（聊天、论坛、朋友圈等）
- 每个 App 一行，折叠状态显示"跟随全局"或"已自定义 N 项"
- 展开后显示和全局一样的分组结构，但只显示**该 App 实际会用到的能力**（如论坛只显示文本和生图）
- 每一项默认"跟随全局"

### 7.5 角色模型设置（子页）

**入口**：分配页底部一行"角色模型设置 · 已自定义 N 个角色 ›"

**子页内容：**

- 列出所有**做过自定义的角色**，每行显示头像、名字、自定义了哪些能力
- 最下方一行灰色文字："其余角色跟随全局 / App 设置"
- 底部按钮"＋ 添加角色"：弹出角色选择器（带搜索，从已有角色中选），选择后进入该角色的设置页

**某个角色的设置页：**

- 和全局一样的分组结构
- 每一项默认"跟随上级"
- 底部"清除该角色的全部自定义"按钮

> 角色专属的音色 ID、外貌描述词等属于**角色资料**，在角色卡里编辑，不在这里。这里只决定"用哪个模型"。

### 7.6 选择器规则（所有分配页通用）

**显示规则（重要）**：未自定义的项不能只写"默认"，必须显示实际生效的值：

```
跟随全局（某中转站 · deepseek-chat）›
```

点击右侧箭头可跳到上一级的对应设置。

**选择弹出层（从底部弹出）：**

- 顶部第一项："跟随上级"
- 下面按站点分组，每组标题为"站点名 · N 个可用模型"
- 只列出**带有当前能力标签且已启用**的模型
- 看图选择器中，同时列出所有带"看图"标签的文本模型
- 支持搜索
- 底部入口"管理站点 ›"，跳回站点 Tab

**原则：分配页只能选择和引用，不能编辑站点或模型本身。**

## 9. 能力与适配器

### 9.1 适配器模式

每种协议写一个适配器，统一对外提供：

```
adapter.listModels(site)            拉取模型列表
adapter.request(site, key, model, 统一请求)   发起请求
adapter.getBalance(site, key)       查询余额（不支持则返回 null）
adapter.test(site, key)             测试连接
```

业务代码只发出统一请求，例如"生成文本""生成一张图""把这句话读出来"，不关心对方是哪家。

### 9.2 第一版需要的适配器

| 适配器 | 覆盖能力 | 说明 |
|---|---|---|
| OpenAI 兼容 | 文本、看图、向量、部分生图/语音 | 最优先。拉取模型用 `GET /models`；文本用 `/chat/completions`；向量用 `/embeddings`；看图在消息里放图片 |
| NovelAI | 生图 | 第二批 |
| MiniMax / Fish Audio / ElevenLabs | 语音 | 第二批，先做一个跑通，再加其余 |
| 生视频 | 生视频 | 最后做。多数为"提交任务 → 轮询结果"模式 |

### 9.3 余额查询

中转站常见的余额接口（如 new-api / one-api 类面板）在 OpenAI 兼容适配器中尝试查询；查询失败或站点不支持时返回 null，界面显示"不支持查询"，**不报错、不打扰用户**。

### 9.4 Token 统计

从接口返回的 `usage` 字段读取输入 / 输出 Token。流式输出时请求中带上 `stream_options: { include_usage: true }`；如果站点不返回用量，日志中 Token 显示为"—"，不要估算。

## 10. 运行时逻辑

### 10.1 统一调用入口

所有 AI 调用只能通过这一个入口：

```
callAI(能力, 请求内容, { appId, roleId })
```

内部流程：

```
1. getProfile(能力, appId, roleId)
   → 先查角色有没有设置
   → 没有就查 App
   → 再没有就用全局
   → 全局也没有 → 提示用户"还没有设置 XX 模型"，并给出跳转到分配页的按钮

2. 如果该能力挂了辅助模型（如提示词改写）
   → 先用辅助模型处理请求内容，再进入下一步

3. 选择 Key（按站点的轮询 / 固定规则，跳过已停用和异常的 Key）

4. 进入限流队列（站点级 + 模型级限制，取更严格的那个）

5. 交给适配器发送请求

6. 失败时：按重试次数重试 → 仍失败且设置了备用模型 → 切换备用模型

7. 写入请求日志（无论成功失败）
```

### 10.2 限流队列

- 每个站点维护一个队列，记录进行中的请求数和最近 60 秒内的请求时间
- 超出并发或速率时：
  - 设置为"排队等待"→ 进入队列，等有空位再发
  - 设置为"直接报错"→ 立即返回错误，提示"该站点请求过于频繁"
- 队列状态供"限制"Tab 实时显示

### 10.3 Key 异常处理

- 同一个 Key 连续失败 3 次（鉴权错误、余额不足类错误）→ 标记为异常，暂时跳过
- 用户在配置 Tab 点击"恢复"或测试成功后解除标记

### 10.4 策略组（后续迭代，第一版不做）

数据结构先预留。接入后，分配选择器中多一种"策略组"选项：

```
策略组 = { id, name, members: [{ siteId, modelId }], mode: '轮流' | '故障转移' }
```

- 轮流：每次请求依次换下一个成员；轮到的成员正在被限流则跳过
- 故障转移：一直用第一个，失败了才换下一个

## 12. 存储与安全

- **站点、分配、设置**：存 IndexedDB（数据量小也可以用 localStorage，但统一用 IndexedDB 更省事）
- **请求日志**：必须存 IndexedDB，按时间建索引，便于清理和筛选
- **Key 只存在用户本地**，任何时候不发送到 API 站点以外的地方
- **导出数据时**提供选项"导出时不包含 Key"，默认勾选，防止用户分享备份时泄露
- **纯前端跨域问题**：部分官方 API 不允许浏览器直接请求。遇到这类错误时，给出明确提示："该站点可能不支持浏览器直连，请使用中转站或自定义代理地址"，不要只显示"请求失败"
