## 用户是谁、怎么跟他配合

- **零编程基础**，靠感觉和截图提需求。中文交流，别用术语。
- 喜欢**一小步一验收**：改完要说清楚"你去看哪里、应该看到什么"。
- 会发参考图（小红书 UI 手册那类），要求"学习一下"。**图不一定全用，但要认真对照。**
- 他经常连续说"继续"表示催促，那就多推进，别停下来问。
- 讨厌：**空荡的留白**、按钮字号过大、圆角套圆角、多余入口。

## 绝对不能做的事

- ❌ 不许编造。没验证的就写「未核实」。
- ❌ 不许擅自改数据表结构、推送远端前要说明（他现在默认允许推送）。
- ❌ 不许整页 `innerHTML` 重渲染（输入框焦点会丢）。
- ❌ 不许 `transition: all`，不许裸色值。
- ❌ 不许引入 AGENTS.md §1 禁止列表里的依赖（React/Tailwind/axios/任何 UI 库）。
- ❌ **不许抄 AGPL/GPL 项目的代码**（SillyTavern、Chatbox、rikkahub、kelivo 等，见 AGENTS.md §6）。

## 验证习惯

改完代码必须：

1. `cd wish-phone && npm run build` 跑通，把**真实输出**贴出来
2. 合规自检：
   ```
   grep -rn "fetch(" src/ --include=*.ts | grep -v "src/ai/"   # 必须为空
   grep -rn "console\." src/                                    # 必须为空
   grep -rn "transition: all" src/                              # 必须为空
   grep -rnE "#[0-9a-fA-F]{3,8}\b" src/features/*/*.css src/ui/*.css   # 必须为空
   ```
3. 告诉用户怎么在手机上确认
