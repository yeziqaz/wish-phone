# 愿望机 · 第一版任务单

> 拆成 9 个小任务，**每个任务都能在手机上肉眼验收**。
> 一次只做一个，做完 → 你在真机上确认 → 再开下一个。
> 技术约束见 [AGENTS.md](../AGENTS.md)，产品定义见 [产品说明书](产品说明书.md)。

---

## 依赖关系

```
T1 骨架 ─→ T2 桌面 ─→ T3 存储 ─→ T4 设置页 ─→ T5 角色 ─→ T6 聊天 ─→ T7 存档/导出
                                                              └─→ T8 PWA
                                                              └─→ T9 CI 出 APK
```

T2 完成后你就能第一次在手机上看到东西（这一步的成就感很关键）。
T6 完成后主线跑通。T7/T8/T9 是「能用」到「能给别人用」的三步。

## T1 · 项目骨架与设计令牌接入

**目标**：一个能跑起来的空壳，设计令牌已经生效，手机上打开是一片黑白色的空页面。

**会创建/修改的文件**
- `package.json` / `vite.config.ts` / `tsconfig.json` / `index.html`
- `src/main.ts`、`src/app.css`
- `src/core/store.ts`（约 40 行）、`src/core/router.ts`（hash 路由）
- `capacitor.config.ts`

**完成标准**
- `npm run dev` 能起服务，`npm run build` 能通过
- 页面背景是 `--bg`、文字是 `--ink`，改 `tokens.css` 里的变量，页面颜色跟着变
- 依赖清单里**没有任何框架**

**怎么验证**
1. 你运行 `npm run dev`，手机连同一个网络打开地址
2. 看到一片浅灰底、黑色标题的页面
3. 把 `tokens.css` 里 `--bg` 改成一个深色值，刷新，页面变深（验证令牌确实生效了）

**风险**
- ⚠️ Node 版本：Vite 8 要求 Node `^20.19 || >=22.12`，本机是 24，OK
- ⚠️ 别顺手引 Tailwind —— 设计令牌已经把这活干了

## T2 · 锁屏 + 桌面 + 果冻反馈

**目标**：看到一部**像手机**的界面 —— 打开先是锁屏（大号时钟 + 日期），上滑进入桌面（一行小状态栏、图标网格、底部 Dock），点上去有果冻回弹。

**会创建/修改的文件**
- `src/features/lockscreen/lockscreen.ts`、`lockscreen.css`
- `src/features/desktop/desktop.ts`、`desktop.css`
- `src/ui/icons/`（内联 SVG，先做 4 个：角色、聊天、设置、帮助）
- `src/app.css`（`.jelly` 类）

**完成标准**
- 每次打开应用先显示锁屏；上滑超过阈值解锁，没拖够弹回
- 锁屏时钟每分钟自动更新，日期显示"10月30日 星期三"这样的中文；桌面顶部只留一行小字状态栏
- 每个 App 只出现一次（网格或 Dock 二选一）
- 图标网格 4 列，图标是**实心**风格，下方有 11px 标签
- 点图标：按下 80ms 快速缩小，松开 650ms 带过冲弹回
- 触控区不小于 44px
- **低端机上不掉帧**

**怎么验证**
1. 手机上打开，先看到锁屏，时钟是不是当前时间
2. 轻拖一点松手 → 弹回；拖过约 1/5 屏高 → 滑开露出桌面
3. 挨个点图标，感受回弹手感 —— 要"Q 弹"，不是"硬邦邦"
4. 故意在桌面上快速连点十几下，看有没有卡顿或闪烁

**风险**
- ⚠️ **绝对不要给所有图标常开 `will-change: transform`** —— 几十个合成层会爆显存，低端安卓直接卡死。只在按下时加、松开后撤
- ⚠️ 状态栏要避开刘海和底部手势区，用 `env(safe-area-inset-*)`
- ⚠️ 这一版桌面是**固定的 4 个图标**，不要提前做拖拽/多页

## T3 · 本地存储地基

**目标**：数据能存进 IndexedDB，关掉再打开还在。这一步**界面上看不出变化**，但后面所有功能都靠它。

**会创建/修改的文件**
- `src/core/db.ts`（`idb` 封装，四张表：characters / conversations / messages / settings）
- `src/core/store.ts`（接上持久化）

**完成标准**
- 四张表和字段定义写好，角色字段**对齐 Character Card V3**
- 数据库版本变更带迁移函数（不许清库）
- 每写一条数据立即落库

**怎么验证**
1. 让 AI 在设置页临时加一个"测试"按钮，写一条数据
2. 关掉浏览器/App，重新打开，点一下读出来 —— 数据还在
3. 清掉这个临时按钮

**风险**
- ⚠️ IndexedDB 是异步打开的，**打开完成前不许读写**，否则直接报错崩掉
- ⚠️ 这是全项目最不该出错的地方 —— 结构一旦上线改了就要迁移，**现在定清楚**

## T4 · API 设置页 + 连通性自检

**目标**：用户能填自己的接口地址、Key、模型名，点一下"测试连接"就知道通没通。

**会创建/修改的文件**
- `src/features/settings/settings.ts`、`settings.css`
- `src/ai/client.ts`（**全项目唯一的 HTTP 出口**）
- `src/ai/types.ts`、`src/ai/errors.ts`

**完成标准**
- 地址栏自动容错：带不带 `/v1`、结尾有没有斜杠、前后有没有空格，都能用
- 有"拉取模型列表"按钮（省得用户手打模型名）
- **测试连接**能把结果分成五类用中文说清楚：跨域 / 401 / 余额 / 连不上 / 服务端错误
- 提供「查看原始错误」折叠区
- Key 默认不明文回显，有"显示"开关
- 有"记住 Key / 仅本次会话"选项

**怎么验证**
1. 填你自己的真实 API 地址和 Key，点测试 → 应显示"连接正常"
2. **故意把 Key 最后一位改错**，点测试 → 应显示"密钥不对"，而不是英文报错
3. 故意填一个不存在的域名 → 应显示"连不上这个地址"
4. 展开原始错误，能看到真实报错

**风险**
- ⚠️ **Key 绝对不能进 `console.log`**，也不能进 URL query
- ⚠️ 请求必须 `credentials: 'omit'`
- ⚠️ 错误**绝不能被当成角色台词存进聊天记录**（这是这类应用最典型的翻车点）

## T5 · 角色系统

**目标**：能新增/编辑/删除/选择角色，重启后当前角色还记得。

**会创建/修改的文件**
- `src/features/character/character.ts`、`character.css`
- `src/ai/` 不动；数据写入走 `core/db.ts`
- 角色卡导入：`src/core/card.ts`（V2/V3 JSON 与 PNG 解析）

**完成标准**
- 角色至少包含：id、名字、头像、人设、开场白
- id 创建后**永不改变**，所有数据按 id 隔离，不靠名字
- 删除角色要二次确认，并说明聊天记录会怎么处理
- **能导入一张现成的角色卡**（JSON 或 PNG），导入后原始 JSON 原样保留
- 重启后当前选中的角色还在

**怎么验证**
1. 新建一个角色，起个名字写句话，保存
2. 关掉应用重开 → 角色还在，且是选中的那个
3. 找一张现成的角色卡（`.json` 或 `.png`）拖进来 → 出现在列表里，名字和开场白都对
4. 删除它 → 有二次确认

**风险**
- ⚠️ **PNG 角色卡解析**：`tEXt` chunk、keyword 是 `chara`（小写），值是「UTF-8 JSON → base64」，**只有一次 base64**。读取时 keyword 要**大小写不敏感**
- ⚠️ 同一张 PNG 可能同时有 `chara` 和 `ccv3` 两个 chunk → **以 ccv3 优先**
- ⚠️ 角色卡里的 `{{char}}` / `{{user}}` 占位符大小写不敏感，必须替换
- ⚠️ 别用猜编码的方式解析文件，统一按 UTF-8

## T6 · 文字聊天（主线跑通）

**目标**：**发消息 → 拿到回复 → 显示成气泡**。这是整个第一版的核心。

**会创建/修改的文件**
- `src/features/chat/chat.ts`、`chat.css`
- `src/ai/client.ts`（补上 chat 方法）

**完成标准**
- 发送后，先出现用户气泡，再出现"正在输入"
- 回复到达后**在本地逐字浮出**（模拟打字感）
- 上下文包含：角色人设 + 开场白 + 最近历史 + 新消息
- 空消息不能发；快速连点不会重复发送
- 长回复能滚动，中文和表情正常
- **错误显示为系统提示，绝不存成角色回复**

**怎么验证**
1. 发一句"在干嘛" → 看到回复一个字一个字浮出来
2. 快速连点发送按钮 5 下 → 只发出去一条
3. **把网络断开**再发 → 应显示"连不上"的提示，**不能**在气泡里显示"连不上"当成角色说的话
4. 发一大段话 → 能正常滚动

**风险**
- ⚠️ 网络请求不能阻塞主线程；切走页面时不许再更新已销毁的界面
- ⚠️ **不许整页 `innerHTML` 重渲染** —— 会把输入框焦点和动画一起毁掉
- ⚠️ 本地逐字播放要能被"跳过"（用户点一下直接看全文）

## T7 · 存档、导出与导入

**目标**：用户能把自己的全部数据导出去、导回来。**这是防 iPhone 清数据的唯一解**。

**会创建/修改的文件**
- `src/core/backup.ts`
- `src/features/settings/settings.ts`（加入口）

**完成标准**
- 导出为**一个 JSON 文件**，包含角色、聊天记录、设置
- **导出内容不含 API Key**（要在界面上写清楚）
- 导入能识别文件是不是本应用导出的，坏文件给出人话提示，不要崩
- 导入前告诉用户：会覆盖还是合并
- 桌面或设置页有显眼入口（一等功能，不是藏在角落）
- 有"清空全部数据"，二次确认

**怎么验证**
1. 导出 → 得到一个 `.json` 文件（手机上应该能存到"文件"App）
2. 清空全部数据 → 界面变空
3. 把刚才的文件导回来 → 角色和聊天记录都回来了
4. 随便选一张图片文件导入 → 应提示"这不是愿望机的备份文件"，不能崩

**风险**
- ⚠️ **iPhone 上 `<a download>` 行为不确定**（未核实）→ 优先用系统的分享功能，失败再退回下载
- ⚠️ 导出必须以导入时的原始 JSON 为基准回写，**不许丢未知字段**

## T8 · PWA 与帮助页

**目标**：能"添加到主屏幕"，断网能打开壳，并有一页讲清楚"为什么连不上"。

**会创建/修改的文件**
- `public/manifest.webmanifest`、图标
- `vite.config.ts`（`vite-plugin-pwa`）
- `src/features/help/help.md`（或 `.ts`）

**完成标准**
- 手机上"添加到主屏幕"后，图标、名称、全屏显示正常
- 断网打开 → 出现应用外壳和友好提示，不是浏览器的"无法访问"
- 启动时申请持久化存储权限
- **iPhone 用户会被主动引导**"分享 → 添加到主屏幕"（否则 7 天后数据会被清）
- 帮助页写清楚：怎么填 API、遇到跨域怎么办、Key 存在哪、隐私边界

**怎么验证**
1. 手机浏览器菜单 → 添加到主屏幕 → 从主屏打开，看是不是全屏、有没有浏览器地址栏
2. 开飞行模式再打开 → 应看到应用界面和"网络不可用"提示
3. 读一遍帮助页，检查有没有一句看不懂的行话

**风险**
- ⚠️ Service Worker 会缓存旧版本 → 更新策略要写清楚，否则用户永远看到旧界面
- ⚠️ 别把 manifest 里的图标路径写错，否则主屏图标是个白方块

## T9 · CI 自动出 APK

**目标**：推代码就自动构建出 APK，不用装 Android Studio。

**会创建/修改的文件**
- `.github/workflows/android.yml`
- `android/` 目录（`npx cap add android` 生成，**必须提交进 Git**）

**完成标准**
- 推送到 main 后，GitHub Actions 自动构建出 debug APK
- 能在 Actions 页面下载到 APK 文件
- 产物保留期设为 14 天（免费额度只有 500MB 存储）

**怎么验证**
1. 推一次代码 → 去仓库的 Actions 页面看有没有在跑
2. 跑完下载 APK → 装到自己手机上
3. 打开 → 界面和网页版一致

**风险**
- ⚠️ **`android/` 是源码不是产物，必须提交**；keystore **绝不能**提交
- ⚠️ workflow 里要写死 `ubuntu-24.04`，不要用 `ubuntu-latest`（版本会漂移）
- ⚠️ 上传产物要加 `if-no-files-found: error`，否则失败时只看到空包，白排查
- ⚠️ 首次构建要下载 Gradle 和依赖，**必须开缓存**，否则每次 8~15 分钟
- ⚠️ 公开仓库日志人人可见，**别把 Key 或签名口令 echo 进日志**
