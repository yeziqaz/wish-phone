> 本文件回答"我们到底在做什么"。技术怎么实现看 [AGENTS.md](../AGENTS.md)，怎么一步步做看 [第一版任务单](第一版任务单.md)。

---

## 一句话

**一部装在自己手机里的 AI 小手机**：有桌面、有自己的 App，还有住在这里的 AI 角色。

---

## 它解决什么问题

现在的 AI 角色聊天工具，基本只有两条路：

- **要你自己跑服务器**（SillyTavern 这类）—— 门槛高，手机用户基本劝退
- **把你的对话和记忆存在别人的服务器上**（各种在线服务）—— 隐私不在自己手里

愿望机走**第三条路**：

> **零后端 · 数据全在你自己设备上 · 你用自己的 API Key · 完全开源**

谁都能部署，部署完就是自己的。

---

## 目标用户

1. 想和 AI 角色长期相处，**但不想折腾服务器**的人
2. **在意隐私**，不想把聊天记录、角色设定交给第三方的人
3. 想**自己改、自己加 App** 的创作者（所以代码要尽量短、依赖要尽量少）

---

## 核心体验（第一版就要跑通的主线）

用普通话描述一遍完整场景：

> 我打开愿望机（一条链接，或者装好的 APK），看到一部小手机。
> 顶上显示现在几点、今天几号；中间是一格一格的图标；底下有一排固定的 Dock。
>
> 我点"角色"图标，看到一个空列表。我点新增，给角色起个名字、写几句设定。
> —— 或者更省事：我直接把手上那张现成的**角色卡**（JSON 或 PNG）拖进来，它就出现在列表里了。
>
> 回到桌面，我点"聊天"，选中刚才那个角色，打字说"在干嘛"。
> 稍等一下，回复一个字一个字地浮出来，像真的在打字。
>
> 我把手机锁屏，过一会儿再打开 —— **记录还在，角色还在，设置还在。**
>
> 我第一次用的时候，是在"设置"里填的自己 API 地址和 Key，填完点了一下"测试连接"，它告诉我通了。

**这条线跑通了，第一版就算成了。**

## 第一版必须有的

| # | 功能 | 为什么必须有 |
|---|---|---|
| 1 | 桌面：时钟、日期、图标网格、Dock | 没有它就不叫"小手机" |
| 2 | 点击的果冻回弹手感 | 这是"质感"的来源，也是文档里反复强调的反馈层 |
| 3 | 角色：新增 / 编辑 / 删除 / 选择，重启后保持 | 主线的起点 |
| 4 | 文字聊天：发送、等回复、逐字浮出、错误提示 | 主线的核心 |
| 5 | 本地存档：关掉再打开数据还在 | 主线的终点，也是验收标准 |
| 6 | API 设置页 + **连通性自检** | 见下方"为什么自检是必须的" |
| 7 | **导出 / 导入 JSON** + 清空全部数据 | 见下方"iPhone 会删你的数据" |
| 8 | PWA：能"添加到主屏幕"、断网能打开壳 | 决定它像不像一个 App |
| 9 | CI 能自动出 debug APK | 否则每次发版都要装 Android Studio |

### 为什么"连通性自检"是必须的

浏览器直连第三方 API 时，如果对方不允许跨域（CORS），**JavaScript 拿不到任何原因**，只能拿到一句 `TypeError: Failed to fetch`。

用户看到的就是"我填完了，点发送，没反应"。

**这一屏决定用户会不会放弃。** 所以自检必须自己区分并翻译成人话：

| 情况 | 告诉用户 |
|---|---|
| 跨域被拒 | 该接口不允许网页直接访问；换接口地址，或用 App 里的「兼容模式」 |
| 401 | Key 不对或已失效，检查有没有复制完整、有没有多余空格 |
| 余额/额度 | 余额不足或额度用完了，去服务商后台看看 |
| 连不上 | 连不上这个地址，可能是网络或地区限制 |
| 5xx | 服务端出错，稍后重试 |

另外要提供一个**「查看原始错误」**的折叠区 —— 用户能自己看到原始报错，能省掉大量求助。

### 为什么导出/导入不能拖到以后

**iPhone 上，如果用户只是用 Safari 打开、没"添加到主屏幕"，那么 7 天不打开，系统会把网站数据全部清空** —— 聊天记录、角色、API Key 一起蒸发。这是 WebKit 官方明确的策略，不是 bug。

所以第一版就必须给用户一条"把数据攥在自己手里"的路。

## 明确暂缓的（第一版不做）

- 语音：TTS、语音通话、情绪识别
- 长期记忆、向量检索
- 世界书、群聊、表情包
- MCP / 工具调用 / 联网搜索
- 多页桌面、小组件、自由拖拽、主题引擎
- **流式输出**（逐字蹦字的网络流）

### 关于流式，要解释清楚

不是我们不想做，是**技术上互斥**：能绕过跨域的原生请求方式，会同时失去流式、失去"停止生成"按钮、失去超时。

所以第一版的做法是：**一次性拿到完整回复，然后在本地一个字一个字地播放出来**。用户看到的仍然是"字一个个蹦出来"，体验几乎无差别，但网页版和 APK 版行为完全一致，还省掉一堆边界问题。

将来如果找到两全其美的方案，再加。

## 数据与隐私（要对用户如实说）

- 所有数据存在**你自己浏览器/App 的本地存储**里
- API Key 只存在**你自己的设备**上；APK 版会存进系统的加密存储
- **我们没有服务器，收不到任何数据**，也看不到你的对话
- 但要说清楚：你的消息会**直接发给你自己填的那个 AI 服务商**，隐私取决于你选谁
- 一键"清空全部数据"随时可用

## 远期设想（不承诺实现）

### 让手机上的 agent 扮演角色

**想法**：手机上已经在跑的 agent（例如 DSH、Operit）接进愿望机，以**某个角色的身份**在小手机里聊天。agent 只拿到「这个角色」的权限，相当于多了一张角色卡，**不掌管整个小手机**。

**大致做法**：在愿望机和 agent 之间放一个用户自己运行的小桥接程序。

```
愿望机 ──普通聊天请求──▶ 桥接程序（对愿望机来说就是一个 OpenAI 兼容地址）
                            │ 请求先挂起，等 agent 来取
                            ▼
                     手机上的 agent，通过 MCP 调用：
                       · 取消息（拿到角色卡 + 聊天记录）
                       · 回复（以角色身份说话）
```

- 在愿望机里，它就是**一个服务商**，把角色绑定到它即可，聊天代码不用改
- 不违反「我们没有服务器」：桥接程序由用户自己运行
- 先试 DSH：它运行在本机，已有「循环等消息 → 回复」的先例（QQ 机器人），且和愿望机走本机地址就能互通

**已知的坑**

- agent 要一直保持运行；回一句可能要十几秒到一分钟，需要给这类服务商单独放宽超时
- **安全**：角色卡里的文字会交给一个能执行操作的 agent，必须让它在受限模式下运行，桥接程序只开放「取消息 / 回复」两个工具
- 跨设备、https 页面连本机 http 地址的浏览器限制、Operit 等软件对 MCP 的支持程度：**未核实**
- 前提：T6 文字聊天完成之后才有地方验证
