## 1. 背景与架构定位

愿望机（WishPhone）是纯前端、零后端、本地优先（Local-First）的 AI 虚拟小手机应用。所有角色数据、会话记录、请求日志、分配配置均沉淀在设备 IndexedDB 中，由用户配置自有 OpenAI 兼容 API。

聊天 APP（即“信息 / 聊天”）是愿望机的**核心体验中枢**。用户通过桌面点击联系人/消息气泡进入，与已创建的角色开展多轮拟真对话，承接文本、生图（画一张）、语音朗读（读出来）及世界书条目命中等多模态交互。

## 2. GitHub 开源生态与优秀范式比对

对社区同类产品与竞品（KakaChat、Mio/SullyOS、freeapp/fuyue、SillyTavern）进行架构剖析，提炼可复用的优秀工程范式：

| 维度 / 项目 | KakaChat (PWA) | Mio / SullyOS (Web/OS) | fuyue / freeapp (Capacitor) | 愿望机（本项目实践） |
|---|---|---|---|---|
| **核心架构** | Vue3 + Pinia + IndexedDB | 原生 JS/React + Context + Worker | 本地优先 + 解耦密钥 + APK | 原生 DOM + 轻量状态 store + IndexedDB (`idb`) |
| **消息流处理** | SSE 流式直连，UI 渐进追加 | 全局状态调度 + 请求防抖 | 解耦 Transport，分流直连与本地转发 | `callText` 统一通道 + 流式逐字回放平滑渲染 |
| **多模态扩展** | 单独路由与弹层 | 桌面多 App 切换，通信靠全局 bus | 抽屉操作栏 + 原生系统通知 | 拟真聊天底部「+」扩展抽屉，等高键盘占位无晃动 |
| **世界书与记忆** | 注入前端提示词引擎 | 记忆宫殿 + 上下文窗口截断 | 提示词装配层与角色设定解耦 | `collectLore` 关键词扫描 + 常驻与动态条目按需组合 |
| **模型切换** | 切换需跳转顶层设置 | 独立控制台调整全局绑定 | 会话内单独切换当前模型 | **角色优先级继承**：会话快捷覆盖 > 角色专属 > App > 全局 |

## 3. API 模块研发全历程踩坑复盘（红线规避清单）

在 API 与模型模块从 1 到 13 步骤的实际交付中，经历了多轮细节调整与用户实机反馈。聊天 APP 的后续开发中必须严格回避同类问题：

### 踩坑 1：水平留白重叠导致的“缩进去一块”
- **根因**：顶层滚动容器 `.api-body` 已自带 `padding: 0 var(--sp-5)`，但子模块及卡片容器（如 `.api-filters`、`.api-models-box`、`.api-summary`）又重复声明了 `margin: 0 var(--sp-5)`，导致多重缩进，卡片宽度不一，视觉极其突兀。
- **规避铁律**：**外层容器统一负责页面水平边界**，内部卡片和列表一律继承 `width: 100%`，绝对禁止在子容器内无意识叠加同等页面边距。

### 踩坑 2：边框套边框（框套框）与视觉层级灾难
- **根因**：外层加了一个描边大框包围，内部小分类又画了一圈完整卡片框，里面每个模型行还各自带边框圆角，形成“框套框套框”，页面像一堆碎片堆叠。
- **规避铁律**：一屏只讲一种主要边界。外层有背景和线框时，内部分组只使用**无边框左对齐小字标题**；行与行之间仅保留轻量分隔线或极小间距（0~4px），主次分明。

### 踩坑 3：软键盘弹起引发的视口错位与输入栏抖动
- **根因**：Android 原生 WebView/浏览器对于软键盘弹出有三种不同行为（缩视口、仅平移、直接覆盖不触发事件）。如果只监听一次 `resize`，会导致输入栏被顶飞或抽屉与键盘切换时高度突变。
- **规避铁律**：
  1. 聊天页固定钉在 `visualViewport` 上，动态计算高度并限制在真实视口。
  2. 记录最近一次测得的真实键盘高度，当打开加号菜单抽屉时，面板容器直接复用等同高度（`--chat-keyboard-height`），保证**切换时输入栏高度完全平稳不动**。

### 踩坑 4：无限下延撑破页面导致核心操作不可见
- **根因**：动态列表项（如上百个模型）无脑垂直排布，导致页面底部的操作按钮（如“重新拉取”）被顶到千像素之外，滑到底部极其痛苦。
- **规避铁律**：超长列表区域必须设定**最大高度上限（如 `max-height: min(52dvh, 520px)`）并在框内独立滚动**，底部关键主行动区（发送、重拉、保存等）固定露在可视区域内。

### 踩坑 5：分类推断颗粒度过细与大小写不规范
- **根因**：推断逻辑直接按版本号切片，导致 `opus-4-5`、`opus-4-6` 碎成无数细组，名字重复展示；未忽略大小写导致 `MiniMax`、`GROK` 被误判为未分类。
- **规避铁律**：业务推断纯函数先归一化文本（小写化、剥离日期与小版本号），聚合成高内聚大组；并在 `tests/` 下补充严密的单元测试防止回退。

## 4. 聊天 APP 核心功能与架构分层设计

聊天模块代码结构划分为四层，严格遵守 `AGENTS.md` 边界规范：

```
src/features/chat/
├── chat.ts               # 聊天主页面：DOM 挂载、事件派发、消息滚动与视口同步
├── chat.css              # 聊天专属样式（严格使用 design/tokens.css 语义变量）
├── chat-compose.ts       # 底部输入栏、发送逻辑、软键盘/抽屉无缝互斥
├── chat-drawer.ts        # 底部加号抽屉：快捷操作（重答、画图、读出来、切换模型、世界书）
├── chat-bubble.ts        # 气泡渲染引擎：文本 Markdown/换行、生图卡片、语音条、长按/点击浮动工具条
└── chat-context.ts       # 会话上下文组装：System Prompt 编排、世界书检索注入、历史截断
```

### 关键业务流与设计约束：

1. **会话与消息落库 (`src/core/db.ts`)**
   - 消息严格包含：`id`, `conversationId`, `role` (`user` | `assistant` | `system`), `content`, `createdAt`, `extra`。
   - 生图、语音等富媒体信息全部收敛在 `extra`（如 `extra.imageUrl`, `extra.audioBlobKey`, `extra.rewritten`），绝不随意改动 IndexedDB 基础表结构。

2. **提示词组装与上下文管理 (`buildSystem`)**
   - 角色信息分段：人设、性格、场景、和用户的关系、示范对话。
   - 世界观与世界书条目：先常驻全进，再根据当前/历史输入关键词由 `collectLore` 动态命中注入。
   - 系统约束行：明确使用第一人称、保持口吻、不解释自己是 AI、符合手机简短聊天习惯。

3. **模型通道调用 (`src/ai/call.ts`)**
   - 文本生成走 `callText`，严格遵守优先级：`会话指定模型 > 角色专属模型 > 聊天 App 模型 > 全局文本模型`。
   - 生图走 `callImage`（带提示词改写与降级回退）。
   - 语音朗读走 `callSpeech`（获取音频 Blob 后前端直接播放，气泡留有重播开关）。

## 5. UI / 排版与移动端交互铁律

严格遵守 `mobile-ui-craft` 与 `design/STYLE.md`：

1. **气泡排布与间距**：
   - 用户消息靠右，采用反色（`background: var(--inverse-bg); color: var(--inverse-ink)`）。
   - 角色消息靠左，采用描边卡片（`background: var(--surface); border: 1px solid var(--line); color: var(--ink)`）。
   - 气泡文本行高 1.6，中文字体渲染自然，最大宽度限制为 `calc(100% - 64px)`，防止贴边。
2. **触控与操作区**：
   - 底部发送按钮、加号按钮、气泡点击菜单热区均保证不小于 **44×44px**。
   - 气泡菜单采用浮动微条，操作项包含「复制」、「重新生成」、「读出来」、「删除」，点击空白处即关闭。
3. **加号抽屉（扩展面板）**：
   - 抽屉面板必须与软键盘等高，点击输入框时光标聚焦、抽屉即时收起，输入框不产生上下晃动。
   - 抽屉内按钮网格排布，图标采用 20~22px 内联 SVG（`src/ui/icons/`）。
4. **色彩与动画红线**：
   - 绝不使用任何裸色值（`#fff`、`rgb()` 一律禁止），全部走语义变量。
   - 动画仅对 `transform` / `opacity` 进行过渡，禁止使用 `transition: all`，避免低端设备掉帧。

## 6. 分阶段研发任务单

| 阶段 | 核心任务 | 交付物 / 验收标准 | 依赖与重点防踩坑 |
|---|---|---|---|
| **Phase 1: 稳定性与底座就绪** | 阶段性 Git 备份、竞品调研报告入库、代码全链路编译测试通过 | 本指南文档入库，`npm run build` 和 `npm test` 50/50 通过 | 确保 dev server 状态健康，端口可连通 |
| **Phase 2: 聊天抽屉快捷换模型** | 在底部加号菜单中新增「切换模型」抽屉卡片，就地弹窗切换当前角色或会话的文本模型 | 聊天中单手 2 次点击完成模型切换，直接调用 `src/ai/call.ts`，无需离开聊天界面 | 遵循外层线框不嵌套、抽屉限高可滚动规范 |
| **Phase 3: 气泡交互与富操作增强** | 气泡点击/长按操作浮条优化（复制、单条重回、语音重播、就地删除消息） | 手机端触控灵敏，操作条不遮挡上一条气泡，支持多媒体卡片 | 触控区 ≥ 44px，事件冒泡严格拦截，支持取消选择 |
| **Phase 4: 多模态生成与状态反馈** | 深度打磨「画一张」画布动画与「读出来」本地播放控制；接入生视频预留卡片 | 画图/语音生成时有平滑占位骨架屏与明确错误友好提示 | 错误提示必须用人话（`ai/errors.ts`），不暴露原生英文字符 |
| **Phase 5: 会话列表与未读/状态流转** | 优化桌面/消息入口的会话列表，展示最后一条消息摘要、时间戳和角色状态点 | 会话按时间倒序排列，删除会话有二次确认，角标不过度冗余 | 状态文本与时间格式对齐，不使用 12px 以下字号 |
