# 手机界面排版与美化

> 这个技能不是灵感库，是**约束 + 自检**。
> 默认审美已经写在 `design/STYLE.md` 和 `design/tokens.css` 里，这里负责「怎么把它排得不难受」。

## 0. 先读两个东西

1. `design/STYLE.md` —— 灰阶、按钮、字号、触控的硬规则
2. `design/tokens.css` —— 只用变量，不写裸色值

**如果这条规则和用户的当次要求冲突，以用户为准，但当场说明后果。**

---

## 1. 先排版面，再写样式

动 CSS 之前，先用文字把这一屏从上到下列出来：

```
[顶栏 44]
[世界标签 44]        ← 这些都是「壳」
[设定摘要 32]
[导入卡 72]
──────────────       ← 第一屏到这里已经 192px 了
[角色卡]
```

三条铁律：

1. **一屏里「壳」不超过两行。** 顶栏之外，再叠标签、筛选、说明，内容就被挤到折叠线以下了。
2. **每个元素都要挣到自己的高度。** 只是「看起来丰富」的计数、角标、空行，删掉。
3. **主行动永远在拇指区。** 底部 1/3；一屏只有一个主按钮。

> 这个项目已经踩过的坑：角色页一度有「世界标签 + 设定摘要 + 导入卡」三层壳，
> 用户第一眼看不到角色。计数角标也是这么被要求删掉的。

---

## 2. 间距：只用 8 的倍数，关系决定距离

| 位置 | 值 |
|---|---|
| 页面左右留白 | 20 或 24 |
| 卡片内边距 | 16 |
| 卡片之间 | 8 |
| 分组之间 | 24 |
| 标题到正文 | 8 |
| 列表行高 | 56~60（带副标题） |
| 标签/胶囊高度 | 28~32，热区补到 44 |

**关系法则**：相关的东西靠得近，不相关的东西离得远。
内部的 8，分组的 24 —— 比例至少 1:2，界面才有「呼吸」。

不要用 `margin-top: 12` 这种随手值。要么 8，要么 16。

---

## 3. 字号：一块区域最多 3 档

项目只有这 6 档：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| display | 28 | 大时钟，别处不用 |
| title | 20 | 页面/档案大标题 |
| lg | 17 | 列表标题、按钮 |
| base | 15 | 正文 |
| sm | 13 | 辅助说明 |
| caption | 12 | 角标、时间 —— **下限** |

- 字重只用 400 / 500 / 600
- 中文正文行高 1.6；大标题 1.25
- 20px 以上标题加 `--tracking-tight`
- 会变的数字加 `.tabular`

**不要**：12px 以下正文、全屏 4 种以上字号、同一行里三种字重。

---

## 4. 边界与圆角：一屏只讲一种「框」

- 卡片：`1px solid var(--line)` + `--surface`，足够了
- 列表：行与行之间一条线，不要每行都包一层框
- 输入框：`--line-strong`
- 圆角只有三档：卡片 14/16、控件 10、胶囊 999
- **不要圆角套圆角**：外层 16 的卡片里，不要再放一个 16 的卡片；内层要小一档
- 阴影只给「浮起来」的东西：弹层、拍立得、悬浮按钮。普通卡片不加阴影

判断方法：截图眯眼看，**如果满屏都是一样粗的框线，说明边界用多了**。

---

## 5. 触控与手机特性

- 任何可点区域 ≥ 44×44；相邻可点元素至少隔 8
- 不依赖 hover；所有操作要能单指点到
- 底部按钮避开 `env(safe-area-inset-bottom)`
- 页面高度用 `100dvh`，不用 `100vh`
- 横向滚动（照片带、标签带）要 `scroll-snap`，并给一个「还有更多」的暗示
- 输入框聚焦时，键盘会顶起页面：不要把它放在屏幕最底部

---

## 6. 表单：一列，标签在上，提示在下

```
标签
[输入框]
一句人话提示（可选）
```

- 手机上**不要并排两个长标签字段**（「和我的关系」+「昵称」并排就会挤）
- 只有两个短字段（如宽高、比例）才并排
- 占位符写例子，不写「请输入」
- 错误提示放在字段下方，用 `--danger`，不要弹窗
- 一屏只留一个主按钮（保存/创建），取消用 `btn--ghost` 或返回

---

## 7. 空、加载、错误、成功

- **空状态**：一句话说清「这里是什么」+ 一个动作。不要只写「暂无数据」
- **加载**：按钮宽度不变，只换文字；不要整页转圈
- **错误**：翻译成人话，说明「怎么办」，不只报错
- **成功**：一行 `field__note is-ok` 就够，不用弹窗

---

## 8. 图片与媒体

- 固定容器比例，`object-fit` 明确：照片用 `contain`（别裁掉人），封面用 `cover`
- 图片必须有宽高或 `aspect-ratio`，避免加载时跳版
- 多图用横向 scroll-snap；给「1 / 3」这类位置提示
- 图片是内容，可以彩色；**框和字仍然黑白灰**

---

## 9. 交付前自检（必须逐条过）

1. 390px 宽下，有没有横向溢出？长英文/长模型 ID 会不会把卡片撑破？
2. 这一屏是不是**只有一个**主按钮？
3. 「壳」是不是超过两行？第一屏能不能看到真正的内容？
4. 相关的两块，距离是不是比不相关的更近？
5. 同一块区域字号超过 3 档了吗？
6. 有没有小于 44 的可点区域？有没有小于 12 的字？
7. 有没有圆角套圆角、框线套框线？
8. 有没有两个一样重的强调块在抢注意力？
9. 空状态有没有给出下一步？
10. 把这一屏和设置页/角色页并排看，像同一个 App 吗？

**任何一条答不上来，就不要说「做好了」。**

---

## 10. 没有截图时怎么检查

这台机器经常截不了图（无障碍没开），所以要靠推算：

- 可用宽度 = 390 − 2×页面留白。按这个宽度算每行能放几个字
- 中文按 1em/字估算：15px 正文一行约 22 个字
- 检查每个固定高度（如照片带 300px）在 844 高的屏幕上占多少，会不会把内容顶下去
- 检查 flex 行有没有 `min-width: 0`，否则长文本不会省略，会把布局撑破
- 检查 `padding` 有没有重复叠加（父级 16 + 子级 16 = 32，通常太多）

## 12. 参考（只学原则，不抄皮）

- Apple Human Interface Guidelines（iOS 的触控、层级、导航）
- Material Design 3（间距、状态、组件）
- Refactoring UI（层级、留白、对比）
- Vercel Web Interface Guidelines（表单、焦点、可访问性）

这三条是共通的：**少即是多、关系决定距离、对比决定层级。**
